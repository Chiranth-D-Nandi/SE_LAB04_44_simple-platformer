PROMPT 2 — IMPLEMENT THE FOUR LAB TASKS
======================================================================

The original platformer has now been cloned and the baseline demonstration has
been recorded.

Please help me implement the four required Lab 4 tasks systematically.

Tasks:
1. Fix platform collision tunneling using an appropriate swept landing check
   and implement a suitable terminal-velocity limit.
2. Add a Game Over screen that displays the final score and waits for user
   input.
3. Add replay functionality with Easy, Medium and Hard difficulty selection,
   as well as an option to exit.
4. Add jump, goal and death sound effects. The sounds should be synthesized
   programmatically rather than requiring external audio assets.

Development requirements:
- Inspect the existing architecture before modifying it.
- Preserve existing functionality unless a change is necessary for one of
  the requirements.
- Keep each task independently identifiable in the Git history.
- Explain the implementation rationale briefly before applying each change.
- Prefer the smallest maintainable change that satisfies the requirement.
- Avoid unnecessary dependencies and external assets.
- After each major change, verify that the project still runs.

Create one Git commit per task with clear, descriptive commit messages.

PROMPT 3 — COLLISION FIX
======================================================================

Analyze the platform collision system and identify why the player can pass
through platforms during fast downward movement.

Implement a robust landing/collision check that prevents tunneling while
preserving normal movement and jumping behaviour.

Also add a reasonable terminal-velocity constraint so that extremely large
downward movement does not undermine the collision logic.

Before implementation:
- Explain the existing failure mode.
- Explain why the proposed collision approach addresses it.
- Mention any relevant edge cases.

After implementation:
- Run the game.
- Verify normal jumping and landing.
- Verify that high-speed downward movement does not allow the player to pass
  through platforms.

Commit this change separately as Task 1.

PROMPT 4 — GAME OVER SYSTEM
======================================================================

Implement a proper Game Over state for the platformer.

Requirements:
- Detect the relevant death conditions already used by the game.
- Stop normal gameplay when the player dies.
- Display a Game Over screen.
- Display the player's final score.
- Wait for an appropriate user input before continuing.
- Preserve the existing score calculation.

Please integrate the feature into the existing game-state structure rather
than adding an unrelated parallel system.

Test:
1. Trigger a death condition.
2. Confirm that the Game Over screen appears.
3. Confirm that the final score is displayed.
4. Confirm that the game responds correctly to the required input.

Commit this change separately as Task 2.

PROMPT 5 — REPLAY AND DIFFICULTY SELECTION
======================================================================

Extend the Game Over/replay flow to support replaying the game with selectable
difficulty levels.

Required difficulty options:
- Easy
- Medium
- Hard

Requirements:
- Provide a clear way to select a difficulty after Game Over.
- Provide an option to exit the game.
- Ensure that restarting creates a clean game state.
- Make the difficulty differences observable in gameplay.
- Display the currently selected difficulty where appropriate.
- Ensure that difficulty selection does not corrupt score, player state or
  other game variables from the previous run.

Please explain briefly which gameplay parameters are affected by difficulty
and why those parameters were selected.

Test every difficulty at least once and verify that replay and exit work.

Commit this change separately as Task 3.
